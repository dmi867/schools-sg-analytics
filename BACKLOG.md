## Из встречи с руководством (transcript 21) — новые метрики

- **Лимит по госпрограмме vs заключённый контракт.** Сейчас `contract_value` берёт
  «Предельную стоимость по объекту» только как запасной вариант, если нет НМЦК. Нужна
  отдельная метрика: лимит по годам из госпрограммы минус сумма реально заключённых
  контрактов — чтобы видеть бюджетные обязательства, не привязанные ни к одному контракту.
- **Разбивка аванс/исполнение по годам.** Сейчас есть только общий флаг «сидит только на
  авансе» (без единого акта). Нужно погодовое: сколько забрано в 2025 авансом/актом,
  сколько в 2026, сколько ещё осталось.
- **Единый риск-сигнал «деньги + срок».** `gap_rub` (разрыв в деньгах) и `days_to_open`
  (срок до ввода) существуют отдельно, не объединены в один сигнал «не успеет ввести из-за
  денег».
- **Рейтинг подрядчиков по всему региону**, не только по нашим 48 школам — отдельная,
  более крупная задача, требует полного Simple List, а не только срез по школам. Пересекается
  с открытым вопросом про расторгнутые контракты (429 по региону, среди наших 48 — ни одного)
  и пересечение подрядчиков по ЦИО/МУН — этот вопрос был задан руководству и остался без ответа.

## Из черновика финансового анализа (второе мнение)

Черновик писался по облегчённому `sg_pay_analysis.json` (без дат, подрядчиков, условий
контрактов) — часть его советов уже закрыта более поздними доработками (разрыв в рублях,
подрядчик в рублях, раздельные светофоры). Не перенесено:

- **Статистический порог красной зоны** (перцентиль/z-score относительно межквартильного
  разброса для своего этапа готовности) вместо фиксированных 15 п.п. на все этапы.
- **Эталонная кривая, взвешенная по объёму контракта**, — параллельно с текущей простой
  медианой (крупный и мелкий объект сейчас в медиане равны).
- **Флаг «типовой аванс, не показатель прогресса»** — объекты с «круглым» % исполнения,
  совпадающим с типовым размером аванса по контракту (на данных 2026 г. — кластер ~10 из 48
  на 27,0–27,3%), нужно помечать отдельно от объектов с реальным прогрессом по актам.
- **Парето/концентрация риска** — таблица топ-N объектов по объёму риска с накопленной
  долей (по каждому срезу: нулевое освоение, красная зона, авансы без актов).
- **Aging акта** — сколько дней прошло с момента достижения объектом очередного этапа
  готовности до поступления акта (или до сегодня, если акта нет). Может потребовать данных
  большей гранулярности, чем сейчас есть.
- **Единый рублёвый риск-скоринг** объекта: гэп в деньгах × бюджетная срочность × доля
  риска подрядчика в его портфеле — одно число для приоритизации, а не отдельный ранг по
  п.п. отклонения.
- **Договорные рычаги на подрядчика** (пени за несдачу исполнительной документации,
  retention 5–10% до приёмки документов, ст. 95 44-ФЗ + реестр недобросовестных поставщиков) —
  это не код, а политика переговоров; требует данных по условиям контрактов, которых сейчас
  нет (уже отмечено как известный пробел на странице методики).

## Известные ограничения логики «СД не подтверждена» (из код-ревью)

- Флаг равно верен и для «смета реально не согласована», и для «объект просто есть в
  Simple List, но поле не заполнено по другой причине» — по одним данным эти два случая
  неотличимы. Сейчас для всех 48 школ (кроме одной) это не создаёт ложных срабатываний,
  но при добавлении новых объектов стоит перепроверять.
- `agreed_cost` копится «вперёд» (`or prev.get(...)`) и не сбрасывается между раундами
  экспертизы — если у объекта будет вторая повторная экспертиза с новой (другой) сметой,
  старое согласованное значение может маскировать то, что текущий раунд ещё не согласован.
  Сейчас в данных такого случая нет.
